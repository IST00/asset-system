# 资产系统风险门禁式分阶段试运行设计

## 1. 目标

在不连接正式数据库、不使用正式业务数据的前提下，通过独立环境、模拟数据和分阶段门禁验证资产系统的安全性、环境一致性、核心业务闭环、权限边界、易用性和运维能力，为后续正式上线提供可审计的验收依据。

## 2. 适用范围

- 试运行方式：小范围用户试运行。
- 数据范围：完全模拟的数据，不含真实人员、资产、附件或业务编号。
- 环境范围：独立试运行服务器、独立数据库、独立数据库账号和独立密钥。
- 用户范围：5～10 名业务用户、1 名系统管理员、1 名技术支持人员。
- 建议周期：完成前置门禁后连续运行 3～5 个工作日。
- 不包含：正式数据迁移、正式账号授权、正式生产切换和 Git 历史重写。

## 3. 方案选择

采用“风险门禁式分阶段试运行”。每个阶段必须完成准入检查、执行项目、证据留存、问题整改和出口验收；上一阶段未通过时，不进入下一阶段。

未采用的方案：

- 按功能模块直接顺序测试：容易把环境、安全和权限问题推迟到后期。
- 一次性集中验收：问题来源混杂，缺陷定位和回归成本高。

## 4. 门禁模型

每个阶段统一包含以下五部分：

1. 准入条件：进入该阶段前必须满足的条件。
2. 执行项目：明确的测试、检查或演练内容。
3. 证据留存：版本、时间、执行人、结果、截图和脱敏日志。
4. 缺陷整改：记录严重级别、负责人、期限、修复版本和回归结果。
5. 出口条件：决定是否允许进入下一阶段的量化标准。

所有测试证据必须能关联到以下信息：

- Git 提交或候选版本标识；
- 后端、前端和数据库版本；
- Python、Node.js、pip、npm 版本；
- Python 和 npm 锁文件摘要；
- Docker 镜像标识；
- 模拟数据版本或数据库快照标识；
- 执行时间、执行人和测试环境。

## 5. 缺陷分级和处置

### P0：立即停止

包括凭据泄露、越权访问、试运行连接正式数据、不可恢复的数据破坏、安全日志泄密。发现后立即停止试运行、隔离环境、保留证据并启动安全处置。

### P1：阻断下一阶段

包括登录不可用、核心资产流程中断、资产状态或金额错误、附件丢失、迁移失败、备份无法恢复。修复并完成全量相关回归前不得继续。

### P2：原则上试运行前修复

包括非核心功能异常、错误提示不清、明显性能下降和部分浏览器兼容问题。若确需延期，必须有可行临时方案、负责人和截止日期。

### P3：纳入整改清单

包括轻微样式、文案、间距、Logo 尺寸和非关键交互问题。允许带入小范围试运行，但必须明确负责人和处理时间。

阶段出口统一要求：P0、P1 为零；P2 已修复或获得书面风险接受；所有失败用例已完成修复验证和受影响范围回归。

## 6. 八阶段设计

### 阶段一：环境与安全门禁

目标：证明试运行环境独立、可复现且不会因配置错误泄露数据或凭据。

执行范围：

- 本地、测试、Docker 和试运行服务器统一 Python 3.13。
- Node.js 统一为 22 LTS，npm 使用项目锁定版本。
- 锁定 Python 直接和传递依赖，根项目及前端 npm 依赖均使用 lockfile。
- 在全新虚拟环境、全新 npm 缓存中重新安装依赖。
- 明确并记录 MySQL 版本；目标环境优先使用 MySQL 8.4 LTS。
- 数据库、连接和表统一使用 `utf8mb4`。
- MySQL 会话使用 UTC；后端以 UTC 存储和传输时间，前端以 `Asia/Shanghai` 显示。
- 试运行与生产使用不同的数据库账号、库名、密码和密钥。
- 检查运行时密钥注入、CORS 白名单、日志脱敏和附件访问控制。
- 完成试运行数据库备份和恢复验证。

出口条件：环境一致性检查全部通过，不存在真实凭据、正式数据、通配生产 CORS 或数据库身份混用。

### 阶段二：自动化质量门禁

目标：证明候选版本在锁定环境中能够重复安装、构建和测试。

执行范围：

- 后端 Ruff、格式、Mypy 和全量 Pytest。
- 前端 TypeScript、ESLint、单元测试和生产构建。
- 从空数据库执行全部迁移。
- 从已知上一版本数据库执行升级迁移。
- 检查迁移顺序、重复执行和失败后的处置说明。
- 执行 Python、npm、容器镜像和敏感信息扫描。
- 使用锁文件和无缓存方式重新构建 Docker 镜像。
- 保存构建日志、依赖摘要和镜像标识。

出口条件：零测试失败、零 lint warning、无未接受的高危漏洞，且同一版本可以重复构建。

### 阶段三：核心业务功能门禁

目标：证明资产全生命周期和管理功能可以形成完整闭环。

验证模块：

- 登录、退出、Token 失效、强制改密、账号锁定；
- 用户、角色、权限和组织范围；
- 资产分类、单位、地点、供应商等基础资料；
- 入库申请、审批、资产生成和编码唯一性；
- 资产查询、编辑、批量维护和数据完整度；
- 个人领用、公共领用、归还和调拨；
- 维修、维修完成和报废；
- 盘点创建、扫码、提交、异常处理、结束和重开；
- 审批流配置、通过、驳回、撤回和执行重试；
- 导入预览、错误反馈和确认导入；
- CSV/PDF 导出和过期文件清理；
- 附件上传、封面、下载、作废、类型和大小限制；
- 操作日志、安全事件、系统状态和健康检查。

每个模块覆盖正常流程、异常输入、重复提交、并发修改、权限不足和数据不存在。

出口条件：全部核心业务闭环完成，P0、P1 为零，关键操作均有正确审计记录。

### 阶段四：模拟数据与权限门禁

目标：证明数据隔离、组织边界和角色权限无法被普通操作绕过。

模拟数据基线：

- 3 个组织、5 个部门、10 个地点；
- 5 类资产、3 种计量单位、5 个供应商；
- 50～200 条资产，覆盖闲置、使用中、维修中和已报废；
- 超级管理员、资产管理员、盘点管理员、审批人、普通用户和停用用户；
- 待审批、已通过、已驳回、执行失败和并发修改等业务状态。

权限验证：

- 普通用户不能访问其他组织的数据；
- 管理员不能超出组织授权范围；
- 停用用户和被撤销会话不能继续访问；
- 导出、附件和审计日志遵循相同权限；
- 批量操作不能绕过单条权限规则；
- 模拟数据不包含真实姓名、联系方式、资产编号或附件。

出口条件：权限矩阵全部通过，无越权、无正式数据混入。

### 阶段五：UI、品牌与易用性门禁

目标：移除脚手架痕迹，使系统达到可供真实用户试用的视觉和交互质量。

执行范围：

- 使用公司正式素材替换默认 Logo、favicon 和登录页图标；
- 检查导航、侧边栏、登录页、空状态、打印页和导出文件品牌信息；
- 准备横版、方形、深色背景和浅色背景 Logo；
- 统一系统名称、公司名称、版权、联系人和帮助入口；
- 验证加载、空数据、失败、无权限、404 和 Token 过期状态；
- 验证表格分页、筛选、排序、批量选择和刷新后的状态；
- 检查 1366×768、1920×1080 和常用笔记本分辨率；
- 检查中文日期、北京时间、人民币金额、长文本和换行；
- 检查键盘操作、焦点、对比度和错误提示可理解性。

出口条件：无脚手架品牌残留，主要页面不存在阻碍使用的布局、文案和交互问题。

### 阶段六：小范围用户试运行门禁

目标：在受控环境中验证真实用户能否独立完成高频任务。

执行范围：

- 5～10 名业务用户参与；
- 1 名系统管理员和 1 名技术支持人员值守；
- 连续运行 3～5 个工作日；
- 只使用模拟数据和独立试运行数据库；
- 每日记录登录人数、核心流程完成数、失败请求和慢请求；
- 每日检查数据库连接、磁盘、附件占用、导出文件和错误日志；
- 记录用户疑问、误操作、缺失功能和 P0～P3 缺陷。

出口条件：连续两个工作日无 P0/P1，主要用户可以在少量指导下独立完成核心流程。

### 阶段七：缺陷修复与全量回归门禁

目标：证明试运行期间发现的问题已被修复，且没有破坏已有功能。

执行范围：

- 每个行为缺陷先增加自动化回归用例；
- 修复后重测原始场景及上下游业务；
- 回归权限、审计、并发和迁移行为；
- 重新执行全量后端和前端质量检查；
- 重建镜像并重新部署；
- 重新验证环境隔离、迁移和备份恢复；
- 更新用户手册、管理员手册和已知问题清单。

出口条件：P0/P1 清零，P2 有明确结论，全量检查在最终候选版本上通过。

### 阶段八：正式上线准备门禁

目标：在不直接执行正式上线的情况下，证明人员、流程和技术资产已具备上线条件。

必备条件：

- 确定的生产版本和不可变镜像；
- 生产数据库迁移方案及回退方案；
- 自动备份、保留周期和恢复演练记录；
- 应用、数据库、磁盘、证书和错误率监控；
- 告警联系人和问题升级流程；
- 管理员初始化、密码交接和最小权限授权；
- 部署、故障、凭据轮换、管理员和用户操作手册；
- 上线窗口、变更冻结、验收人和回滚负责人；
- 正式数据初始化和核对方案；
- 上线后首日和首周巡检计划。

出口条件：业务负责人、系统管理员和技术负责人共同确认，才允许另行发起正式上线变更。

## 7. 角色与责任

- 业务负责人：确认业务场景、模拟数据和最终验收结果。
- 系统管理员：准备账号权限、环境配置、备份和日常巡检。
- 测试执行人：按用例执行、保存证据、提交缺陷和完成回归。
- 开发人员：分析缺陷、补充回归测试、修复并提供候选版本。
- 技术负责人：主持阶段门禁评审，决定阻断、继续或风险接受。
- 数据库/平台管理员：管理数据库账号、最小权限、凭据轮换、备份和恢复。

## 8. 证据与交付物

每个阶段至少产生：

- 可勾选的执行记录；
- 测试结果和脱敏日志；
- 缺陷清单及回归状态；
- 环境和版本清单；
- 数据库快照或备份标识；
- 阶段出口评审结论。

最终交付物包括试运行总结、未解决风险、正式上线前置条件、运维手册和各方验收记录。

## 9. 停止和回退条件

出现以下任一情况立即停止当前阶段：

- 发现 P0；
- 试运行连接到正式数据库或正式第三方系统；
- 备份不可用或无法恢复；
- 权限隔离失效；
- 数据出现无法解释的丢失、重复或状态错乱；
- 环境版本或依赖与冻结清单不一致。

停止后保留日志和快照，回退到试运行前数据库快照及上一可验证镜像。不得通过关闭安全门禁、恢复旧凭据或绕过测试继续运行。
