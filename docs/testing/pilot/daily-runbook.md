# 小范围试运行每日运行手册

适用范围：5～10 名业务用户、1 名系统管理员、1 名技术支持人员，连续 3～5 个工作日，仅使用 `pilot` 独立环境和 `pilot-sim-v1` 模拟数据。

## 固定原则

- 候选 Git commit、镜像和锁文件在当日开始前冻结；中途部署修复即结束当日记录，重新执行受影响门禁后再开始新一日；
- 不接入正式数据库、正式对象存储、正式飞书/邮件等第三方系统；
- 日志和证据不得包含密码、Token、数据库密码、完整连接串或附件内容；
- 用户只使用 `sim_*` 账号和 `SIM-*` 数据；
- 所有问题先登记 `defect-register.md`，再修复和回归。

## 角色和值守

| 角色 | 当日职责 |
| --- | --- |
| 业务用户 | 执行分配的高频任务，记录疑问、误操作和预期差异 |
| 系统管理员 | 开闭场检查、账号、备份、容量和环境隔离 |
| 技术支持 | 观察错误/慢请求，收集脱敏证据，协助复现但不代替用户完成流程 |
| 开发人员 | 分析缺陷；行为修复先补自动化回归用例 |
| 技术负责人 | 判断 P0/P1 停止、P2 风险接受和次日是否继续 |

## 当日业务任务

每位用户至少独立完成：登录/改密、查询筛选、查看详情、一次本人可执行的写操作、一次无权限验证。资产管理员完成入库或资产维护闭环；审批人完成通过与驳回；盘点管理员完成发布、扫码提交和异常处理。技术支持不得直接告诉用户按钮路径，先观察能否借助页面文案独立完成。

## 立即停止条件

出现任一条件立即停止当日及后续试运行，隔离环境并保留脱敏证据：

- 任意 P0；
- 连接正式数据库、正式附件或正式第三方系统；
- 跨组织访问、停用用户继续访问或批量操作越权；
- 备份失败、恢复不可用或快照无法识别；
- 无法解释的资产丢失、重复、金额或状态错乱；
- Python/Node/pip/npm/MySQL、锁文件或镜像与冻结记录不一致；
- 日志打印密码、Token、数据库密码或附件内容。
