# 缺陷回归与正式上线准备门禁

本清单只判断“是否具备另行发起正式上线变更的条件”，不授权连接正式环境、迁移正式数据或执行生产切换。

## 最终候选版本

- [ ] Git commit 已冻结，工作区无未审查文件；
- [ ] 后端、前端和运行环境均来自同一候选版本；
- [ ] 镜像使用不可变 digest，不使用可漂移的 `latest`；
- [ ] Python/npm 锁文件 SHA-256 与门禁记录一致；
- [ ] 依赖、镜像和模拟数据版本已归档。

## 全量回归

- [ ] 每个行为缺陷先有失败回归用例，再修复至通过；
- [ ] 原始场景、上游、下游、权限、审计和并发均已回归；
- [ ] Ruff、格式、Mypy、Pytest 全部通过且零告警；
- [ ] TypeScript、ESLint、前端测试和生产构建全部通过；
- [ ] 所有迁移可从空库执行到 head，重复 upgrade 保持 head；
- [ ] 最终镜像在无缓存构建和全新安装中通过。

## 安全与供应链

- [ ] 仓库敏感信息扫描无真实凭据；
- [ ] Python 依赖漏洞扫描无未接受的高危/严重漏洞；
- [ ] 根项目和前端 npm audit 无未接受的高危/严重漏洞；
- [ ] 容器镜像系统包和应用依赖扫描有归档报告；
- [ ] 生产 `SECRET_KEY`、`JWT_SECRET`、数据库密码由部署环境注入；
- [ ] 生产 CORS 是明确 HTTPS 白名单且不含 `*`；
- [ ] 日志抽查不含密码、Token、数据库密码、连接串密码或附件内容；
- [ ] 试运行和生产数据库账号、库名、密码、密钥完全不同；
- [ ] 管理员、数据库账号和服务账号满足最小权限。

扫描工具、版本、漏洞库时间和报告摘要必须记录；工具缺失或无法更新漏洞库时，本项为 `BLOCKED`，不能写“未发现漏洞”。

## 数据库、迁移与回退

- [ ] 目标 MySQL 版本为 8.4.x，server/database/connection 均为 `utf8mb4`；
- [ ] MySQL 会话 UTC，后端 UTC 存储/传输，前端北京时间展示；
- [ ] 生产迁移脚本、预计耗时、锁表影响和执行负责人明确；
- [ ] 迁移前备份、迁移后核对和失败回退步骤可执行；
- [ ] 在独立恢复库完成恢复演练，迁移 head 与关键表计数一致；
- [ ] 正式数据初始化、去重、核对和签字方案已批准；
- [ ] 附件迁移/初始化方案包含完整性摘要和权限核对。

## 备份与恢复

- [ ] 数据库和附件自动备份计划已配置；
- [ ] 保留周期、异地/隔离副本和加密策略明确；
- [ ] 最近一次恢复演练记录恢复点、恢复时长和数据核对结果；
- [ ] 备份失败告警能到达值班联系人；
- [ ] 恢复操作手册不依赖单一个人或未记录的密码。

## 监控、容量和告警

- [ ] 应用存活、就绪、5xx、延迟、请求量和登录失败可观测；
- [ ] 数据库连接、慢查询、容量、备份和复制状态可观测；
- [ ] CPU、内存、磁盘、附件目录和导出目录设置阈值；
- [ ] TLS 证书到期监控和续期负责人明确；
- [ ] 告警联系人、值班表、升级路径和静默规则已演练；
- [ ] 容量评估覆盖首日、首周和三个月增长。

## 人员、手册和变更

- [ ] 部署手册、故障手册、凭据轮换手册齐备；
- [ ] 管理员手册、用户手册和已知问题清单齐备；
- [ ] 初始管理员建立、强制改密和密码交接流程安全；
- [ ] 上线窗口、变更冻结时间、业务验收人和技术负责人明确；
- [ ] 回滚触发条件、回滚负责人和业务沟通模板明确；
