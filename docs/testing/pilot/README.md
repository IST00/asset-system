# 小范围试运行证据索引

范围：5～10 名用户，连续 3～5 个工作日，只使用模拟数据和独立试运行数据库。任何阶段都不得连接正式数据库、正式对象存储或正式第三方系统。

## 执行顺序

1. 环境与安全
2. 自动化质量
3. 核心业务
4. 模拟数据与权限
5. 品牌与易用性
6. 小范围试运行
7. 缺陷回归
8. 正式上线准备

上一阶段未签署出口结论时，不得进入下一阶段。候选版本、镜像或模拟数据快照发生变化时，从受影响的最早阶段重新执行。

## 阻断规则

- P0：立即停止并隔离环境，保留脱敏日志和数据库快照。
- P1：修复并完成相关全量回归后才能继续。
- P2：原则上在试运行前修复；风险接受必须写明负责人、临时措施和期限。
- P3：可进入整改清单，但必须有负责人和期限。
- 每个阶段 P0/P1 为零后才能签署出口结论。
- `RISK_ACCEPTED` 不得用于 P0/P1。

## 每次执行必须记录

- Git commit、候选版本和不可变镜像标识；
- Python、Node.js、npm、pip、MySQL 版本；
- Python/npm 锁文件 SHA-256 摘要；
- 数据库库名和账号只记录非敏感标识，不记录密码或连接串；
- 模拟数据版本及数据库快照标识；
- 执行人、开始/结束时间和试运行环境标识；
- 用例结果、缺陷编号、脱敏日志、截图或报告位置；
- 业务负责人、系统管理员和技术负责人的阶段结论。

## 证据目录建议

每次执行复制 `gate-record-template.md`，按 `YYYY-MM-DD-阶段-候选版本.md` 命名。截图、报告和日志存放在受控证据库，本仓只保存脱敏后的索引或摘要，禁止提交密码、Token、数据库连接串、真实附件和真实业务数据。

## 配套文件

- `gate-record-template.md`：阶段准入、结果和签署模板；
- `defect-register.md`：P0～P3 缺陷登记；
- `functional-checklist.md`：核心业务用例；
- `permission-matrix.md`：角色、组织和数据范围权限矩阵；
- `simulation-data-catalog.md`：确定性模拟数据基线；
- `brand-and-usability-checklist.md`：品牌、状态页、分辨率和易用性检查；
- `coverage-baseline.md`：后端覆盖率证据、低覆盖核心模块和补测优先级；
- `daily-runbook.md`：3～5 日试运行每日操作；
- `release-readiness.md`：回归和正式上线准备门禁。
