# 产品文档使用说明

[`资产系统建设方案.md`](./资产系统建设方案.md) 是当前资产系统的产品需求事实源。文件从原始文档完整复制，保留所有背景、规则、确认记录和早期技术建议。

## 规则解释顺序

当同一文档中的概括性描述和后续确认记录不一致时，按以下顺序解释：

1. 用户最新明确确认的需求。
2. 建设方案第 14 章“需求确认记录”中的具体结论。
3. 建设方案前面章节的通用设计和建议。

例如，“所有资产操作都需要审批”是通用原则，但维修、公共资产投入使用等操作是否审批，应以第 14 章对应确认记录为准。

## 当前仓库已经确认的技术差异

建设方案包含项目早期技术建议。实际开发必须以当前仓库及项目级指令为准：

| 建设方案早期建议 | 当前仓库实际实现 |
| --- | --- |
| Python 3.12 + FastAPI | Python 3.13 + Flask 3 |
| Vue 3 + Naive UI | React 18 + TypeScript + Vite 5 |
| Redis 7 | 不使用 Redis；不保留检查、配置、Compose 服务或专用依赖 |
| routes → controller → service → repository | Blueprint/API → services → repositories → models |
| 常规 REST 动词 | 业务接口只使用 GET 和 POST |

这些差异只影响技术落地，不改变已经确认的资产业务规则。后续若再次调整技术方案，应同步更新本说明和相关工程约定。

## AI 开发规则

开始一个业务功能前：

1. 定位建设方案中的对应章节和第 14 章确认记录。
2. 把规则整理成独立设计规格，不直接照搬早期目录或框架代码。
3. 明确与其它功能共享的状态、审批、锁定、履历和审计契约。
4. 设计经用户确认后再制定测试驱动实施计划。
5. 开发完成后执行独立只读六维审查和修复复验循环。
