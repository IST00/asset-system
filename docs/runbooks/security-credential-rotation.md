# 数据库凭据轮换与环境隔离操作手册

## 适用范围与状态边界

本手册适用于小范围试运行和正式环境。任何曾提交到 Git 的数据库凭据都必须视为已泄露。删除工作树中的值只能阻止继续传播，不能完成数据库平台上的密码轮换，也不能清除 Git 历史。

数据库或部署平台管理员必须完成账号创建、授权、撤销、应用重启和审计确认；在管理员确认前，不得把“仓库已清理”记录为“凭据已轮换”。操作过程禁止在工单、聊天、日志或命令输出中粘贴真实主机、用户名、密码、连接串、Token 或密钥管理器路径。

## 紧急轮换步骤

1. 将所有曾提交到 `.env.dev` 的凭据标记为已泄露，并停止向任何新环境分发这些值。
2. 为试运行环境创建新的数据库账号，只授予试运行数据库所需的最小权限。
3. 为正式环境创建另一个数据库账号，只授予正式数据库所需的最小权限；账号和库名均不得与试运行环境相同。
4. 将 `SECRET_KEY`、`JWT_SECRET`、数据库密码及其他真实敏感值写入部署环境或密钥管理器。仓库文件只能保留占位值或本地模拟配置。
5. 在撤销旧账号前，使用新账号完成迁移检查、登录、readiness 检查和至少一笔可回滚的读写验证。
6. 新凭据验证成功后，立即轮换或撤销先前提交过的数据库账号，并确认其已有会话被终止。
7. 重启试运行和正式应用，使进程只使用新注入的值；不得通过回退到旧账号解决启动失败。
8. 查看数据库提供商审计日志，确认旧账号在撤销后不再被使用，并排查未知来源的历史访问。
9. 保存轮换时间、执行人、受影响环境、验证结果和旧账号撤销状态；记录不得包含凭据值。
10. 不自动重写 Git 历史。如果组织策略要求彻底移除历史内容，应另行安排协调后的 `git filter-repo` 操作，因为它会改写所有克隆、分支和开放中的变更。

## 部署前门禁

准备好两个未纳入 Git 的环境文件后，从仓库根目录执行：

```bash
back/.venv/bin/python scripts/check_environment_isolation.py \
  back/.env.pilot back/.env.deploy
```

脚本必须返回 0，并且只输出“数据库身份不同”的结论，不输出任何值。返回 1 表示 `DB_USER` 或 `DB_NAME` 被共用；返回 2 表示文件不可读或缺少必需键。两类错误都必须阻止部署。

随后启动一次目标 profile。`DEPLOYMENT_STAGE=pilot` 或 `production` 会启用运行时门禁；以下任一情况都会在日志和数据库初始化前拒绝启动：

- `SECRET_KEY` 或 `JWT_SECRET` 缺失、过短或仍是占位值；
- 数据库连接不是显式注入的非占位 MySQL 配置；
- CORS 缺失、包含 `*`、仍是占位值或包含非 HTTPS 来源；
- 部署阶段名称不受支持。

## 验证清单

- [ ] 试运行与正式环境的 `DB_USER` 不同。
- [ ] 试运行与正式环境的 `DB_NAME` 不同。
- [ ] 两个数据库账号都只有各自数据库所需的最小权限。
- [ ] 数据库迁移可读取并保持在预期版本。
- [ ] 登录可以签发新 JWT，旧进程已重启。
- [ ] readiness 返回 HTTP 200，数据库检查为正常。
- [ ] 已完成一笔可回滚的读取和写入验证。
- [ ] 日志中没有密码、Token、数据库密码或附件内容。
- [ ] 旧账号已撤销或密码已轮换，旧会话已终止。
- [ ] 数据库提供商审计日志中没有旧账号的后续访问。

## 异常与回退

新账号验证失败时，暂停上线并修正授权或注入配置。不要恢复已泄露的旧账号；如必须重新生成凭据，应创建另一组新凭据并重复全部验证。涉及 Git 历史重写、生产数据恢复或跨环境数据迁移时，必须另行审批和安排维护窗口。
