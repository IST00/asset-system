# 资产系统全局布局与首页仪表盘设计

## 1. 目标与范围

本轮建立资产系统前端的共享视觉基础，并完成首个可复用页面骨架。实现范围只包括：

- 统一主题与设计变量；
- 全局应用布局；
- 桌面端与移动端导航；
- 首页资产仪表盘；
- 首页所需的通用展示组件及状态组件。

资产台账、盘点、审批、导入导出等业务页面不在本轮实现，但后续必须复用本轮形成的主题、布局和通用组件。

## 2. 需求依据与技术边界

业务信息架构以 `docs/资产系统建设方案.md` 为依据，布局层次参考 `docs/20260717-174611.jpg` 至 `docs/20260717-174621.jpg` 四张原型图。

原型图仅作为布局、信息密度和模块层次的参考，不复制其深色背景。建设方案中的 Vue 3、Naive UI 和 FastAPI 技术描述不适用于当前仓库。实际实现遵循当前项目约定：

- React 18 + TypeScript + Vite；
- Ant Design 5；
- Lucide React 图标；
- React Query 管理服务端数据；
- Zustand 只管理登录态和真正的全局 UI 状态；
- 所有 HTTP 请求通过 `@/api/http`；
- 只使用 `@/` 路径别名；
- 不新增 UI、图表或样式依赖。

## 3. 视觉方向

采用清晰、克制的浅色后台界面：

- 主背景为浅灰白；
- 内容面板为白色，使用轻边框区分层级；
- 蓝色作为品牌色和主要交互色；
- 绿色、橙色、红色只用于成功、提醒、异常等业务语义；
- 阴影仅用于需要强调层级的浮层，不给所有卡片增加厚重阴影；
- 页面不使用毛玻璃、复杂滤镜或装饰性渐变；
- 内容密度参考原型图，但通过留白和字体层级提升可读性。

主题值集中管理。页面和业务组件不得散落硬编码颜色、圆角、阴影或重复尺寸。后续调整主色、圆角、页面间距、导航宽度和内容密度时，应能通过少量集中配置完成。

## 4. 全局布局

### 4.1 桌面端

- 左侧使用约 72px 的窄导航栏，只显示图标；
- 导航项悬停时显示名称，当前模块使用蓝色背景与明确的选中状态；
- 顶部区域保持轻量，只放页面标题或面包屑、通知入口和用户入口；
- 主内容区使用统一水平留白和最大宽度，避免在超宽显示器上无限拉伸；
- 页面标题、辅助说明、主要操作和内容区使用统一的垂直节奏。

### 4.2 移动端

- 不直接缩小桌面端侧边栏和复杂表格；
- 底部导航固定提供首页、我的资产、盘点和个人中心四个高频入口；
- 管理员专用及其它低频模块通过“更多”抽屉进入，不把完整桌面菜单压入底部导航；
- 首页统计卡片使用单列或双列布局；
- 桌面端表格类页面在移动端使用专用列表或详情流；
- 手机端重点承载本人资产、扫码盘点、领用确认、退库、资产详情和盘点处理。

## 5. 首页信息架构

首页按照以下顺序组织：

1. 页面标题、日期和必要的用户上下文；
2. 核心指标；
3. 快捷操作和待办事项；
4. 当前盘点任务和异常提醒；
5. 资产分类、状态及月度趋势统计。

### 5.1 核心指标

首行显示：

- 资产总数；
- 闲置数量；
- 在用数量；
- 维修中数量。

报废数量进入状态汇总，不继续增加首屏指标卡数量。金额属于敏感字段，只有拥有金额查看权限的用户才能看到相关统计。

### 5.2 快捷操作

提供以下入口，并根据权限决定是否显示：

- 资产入库；
- Excel 导入；
- 创建盘点；
- 打印标签。

快捷操作只负责进入对应流程，不在首页嵌入复杂表单。

### 5.3 待办与异常

优先展示真正需要用户处理的事项：

- 待审批；
- 盘点异常；
- 待补充资料；
- 离职员工名下资产。

每项显示数量、简短状态和进入详情的操作。无权限的事项不显示，数量为零时使用低干扰状态，不制造无意义警报。

### 5.4 盘点进度

展示当前盘点任务名称、完成率、已盘点、待盘点和异常数量，并提供进入任务的入口。没有进行中任务时显示统一空状态。

### 5.5 统计区域

展示：

- 资产分类分布；
- 资产状态分布；
- 月度入库与报废趋势。

第一版优先使用 AntD 现有能力、进度条和轻量 CSS/SVG 表达，不引入图表库。统计图无法清晰表达时，优先使用排序列表和数值，而不是为了视觉效果制作难读的图形。

## 6. 前端结构

建议结构如下：

```text
src/
  theme/
    index.ts
    tokens.ts
  layouts/
    AppShell/
  config/
    navigation.tsx
  components/
    ui/
      PageHeader/
      MetricCard/
      StatusTag/
      EmptyState/
      ErrorState/
  features/
    dashboard/
      components/
      dashboardData.ts
      types.ts
  pages/
    Home.tsx
```

目录可根据实际组件数量适当合并，避免只有一个简单文件的空目录。组件边界按职责划分，不把首页和布局全部堆进一个文件。

## 7. 主题与复用策略

- AntD 主题通过 `ConfigProvider` 统一配置；
- 非 AntD 样式使用共享设计变量；
- 页面背景、内容宽度、导航宽度和断点集中管理；
- 通用组件只包含可复用展示逻辑，不耦合首页业务字段；
- 首页专属模块放在 `features/dashboard/`；
- 菜单名称、图标、路由和权限标识集中在导航配置中；
- 所有图标来自 Lucide React，并统一尺寸、线宽和选中状态；
- 面向用户的新增文案进入 i18n 资源，不在 JSX 中散落硬编码中文。

## 8. 数据流与状态

最终服务端数据通过 React Query 获取，请求函数放在 `src/api/` 并使用 `@/api/http`。首页不把远端统计数据放入 Zustand。

后端接口尚未稳定时，允许使用集中、带类型的演示数据完成页面展示，但必须满足：

- 演示数据与组件分离；
- 类型与预期接口字段一致；
- 页面组件只依赖明确的数据结构；
- 接口接入时只替换数据源和查询逻辑，不重写布局组件。

组件内部展开、折叠和移动端抽屉等状态使用 `useState`。菜单权限来自登录用户权限信息，并在导航配置层过滤；前端隐藏只改善体验，后端仍负责真正的权限校验。

## 9. 加载、空状态与错误处理

- 首次加载使用与最终布局一致的骨架屏，避免页面跳动；
- 某个统计模块失败时只影响该模块，并提供重试入口；
- 首页整体鉴权失败由统一 HTTP 拦截器处理；
- 没有进行中盘点、没有待办或没有统计数据时使用统一空状态；
- 无权限与无数据是两种不同状态，不向无权限用户暴露受限字段名称或数量；
- 错误文案通过 i18n 管理，不直接显示未经处理的服务端异常文本。

## 10. 兼容性与性能

- 不依赖 CSS `gap`，相邻间距使用 margin、padding 或兼容的 AntD 布局能力；
- 不使用 `backdrop-filter`、`position: sticky`、容器查询和复杂滤镜；
- 新浏览器 API 必须特性检测并提供降级；
- 首页模块按稳定顺序渲染，避免频繁深拷贝和无意义重计算；
- 图表和装饰不阻塞核心数字、待办和导航；
- 动效只用于必要的状态反馈，并尊重 `prefers-reduced-motion`。

## 11. 验证与验收

代码检查：

- `npm run type-check`；
- `npm run lint`；
- `npm run build`。

视觉与交互检查：

- 桌面端验证窄侧栏、内容最大宽度、首页模块层级和文字可读性；
- 小屏笔记本验证内容不拥挤、不出现横向溢出；
- 手机宽度验证导航切换、指标卡换行和待办列表；
- 验证加载、空数据、局部错误和无权限状态；
- 验证快捷操作、菜单和待办入口具有清晰的悬停、聚焦和选中状态；
- 将最终页面截图与四张原型图比较，重点检查布局关系、信息密度和模块层级，不要求复制深色配色。

## 12. 明确不做

本轮不实现以下内容：

- 资产台账完整列表和详情；
- 盘点业务流程；
- 审批流程；
- Excel 实际上传和导入；
- 图表库接入；
- 后端接口或数据库修改；
- 深色主题切换；
- 原生 App 或离线能力。
